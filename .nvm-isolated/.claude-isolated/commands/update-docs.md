Обнови граф знаний (по коду) и документацию (по lat.md) по итогам доработок. Используется graphify и lat.

## Разделение ответственности

| Инструмент | Домен | Файлы |
|------------|-------|-------|
| `graphify` | Код, архитектура, зависимости | `*.sh`, `*.py`, `*.js`, `*.ts` и любые не-md изменения |
| `lat` | Архитектурные решения, WHY, `[[ссылки]]` | `lat.md/`, связанные секции |

Деление — про то, какой инструмент ЧТО курирует, не про фильтрацию входа. graphify
строит единый граф (узлы кода + узлы doc-ов); `lat.md/` — отдельный курируемый слой WHY.

## Алгоритм

1. **Определи scope изменений (справочно — для отчёта и Phase 3)**
   - `git diff HEAD --name-only` — НЕкоммиченные правки. Если доработки уже закоммичены,
     diff пуст → возьми диапазон: `git diff <base>..HEAD --name-only` (напр. `origin/master..HEAD`).
   - Если передан путь в `$ARGUMENTS` — ограничь им ручную часть (Phase 3).
   - Если изменений нет — сообщи: «Нет изменений. Укажи путь явно или убедись в наличии diff.»
   - Список справочный: graphify в Phase 1 список файлов НЕ принимает — определяет scope сам (см. ниже).

2. **Phase 1: Обнови граф кода** — `/graphify --update`
   - `--update` инкрементальный: graphify сам диффит текущее дерево против своего
     `.graphify/manifest.json`, переизвлекает только новые/изменённые файлы, чистит узлы удалённых.
     Передавать список файлов бесполезно — он игнорируется.
   - Следствие (by design): подхватываются ВСЕ изменения с последней сборки графа,
     не только текущей сессии (напр. чужие правки в `normalize_paths.py` и т.п.).
   - Только код (.py/.ts/.sh/...) → AST-only, без LLM (быстро/дёшево). Есть doc-изменения
     (.md и пр.) → запускаются semantic-субагенты.
   - Дождись завершения; в отчёт — diff графа (+N узлов / +M рёбер).

3. **Phase 2: Проверь целостность документации** — вызови skill `lat-check`
   - `Skill(lat-check)` в директории проекта (binary не в PATH вне iclaude)
   - exit 0 → continue; exit 1 → выведи broken refs, предупреди пользователя

4. **Phase 3: Обнови затронутые секции в lat.md/ (вручную)**
   - `lat section` / `lat refs` — read-only (флага `--update` НЕТ). Секции lat.md/ —
     курируемый markdown, правится руками через Read/Edit.
   - Найди затронутое: `lat refs "<file|section>"`, `lat section "<query>"` →
     какие секции ссылаются на изменённый код/концепт.
   - Отредактируй/добавь секции под новую функциональность (новый модуль, хук, флаг,
     арх-решение). Лидирующий абзац секции — ≤250 символов (валидирует `lat check`).
   - Клади в правильную по смыслу секцию; не создавай орфанные секции без входящих ссылок.
   - DoD: все связанные секции актуальны; `lat check` → exit 0.

5. **Отчёт**

```
## Обновление знаний [дата]

### Scope
- Код (graphify): <список файлов или "нет изменений">
- Документация (lat): <список файлов или "нет изменений">

### Граф кода (graphify)
- Статус: обновлён / пропущен / ошибка (+N узлов / +M рёбер)

### Документация (lat)
- Phase 2 (lat check): OK / broken refs: <список>
- Phase 3 (правки lat.md/ вручную): обновлено <N> секций / пропущено; lat check exit 0
```
