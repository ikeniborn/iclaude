Проверь план внимательно на соответствие спецификации. Проверь на наличие ошибок.

Поддерживаемые аргументы:
- Путь к файлу плана — если не передан, ищи в `docs/plans/`
- Путь к спецификации — если не передан, ищи SPEC.md, PRD.md, docs/spec* рядом с планом

## Алгоритм

1. **Определи scope**
   - Если имя/тема задачи известна из контекста разговора — ищи файл по имени в `docs/superpowers/plans/`; спецификацию — по тому же имени в `docs/superpowers/specs/`
   - Если передан путь в `$ARGUMENTS` — работай с указанным планом
   - Иначе: ищи последний изменённый файл в `docs/superpowers/plans/`
   - Если не найден — сообщи: «Не найден план. Укажи путь: `/check-plan path/to/plan.md`.»
   - Найди спецификацию: `docs/superpowers/specs/` по совпадению имени, иначе последний изменённый файл там

2. **Прочитай план и спецификацию**
   - Выдели все шаги/задачи плана с их критериями готовности
   - Выдели все требования спецификации

3. **Проверь соответствие плана спецификации**
   - Каждое требование спецификации покрыто хотя бы одним шагом плана?
   - Есть ли шаги плана, не связанные ни с одним требованием (лишние)?
   - Порядок шагов логически корректен (нет зависимостей нарушен)?
   - Критерии готовности шагов измеримы и верифицируемы?

4. **Проверь внутренние ошибки плана**
   - Нет ли циклических зависимостей между шагами?
   - Нет ли шагов без чёткого результата («проработать», «изучить» без выхода)?
   - Нет ли потерянных плейсхолдеров (TODO, TBD, ???)?
   - Нет ли дублирующихся шагов?
   - Реалистичны ли оценки (если указаны)?

5. **Составь отчёт** (см. формат ниже)
   - `[CRITICAL]` — требование не покрыто планом, нарушена зависимость, циклическая ссылка
   - `[WARNING]` — шаг без результата, нет критерия готовности, лишний шаг
   - `[INFO]` — стиль, минорные улучшения

## Правила

**Запрещено:**
- Редактировать план или спецификацию без явного запроса
- Придумывать требования, которых нет в спецификации
- Писать «шаг подразумевает» без конкретной ссылки на текст плана

## Формат вывода

```
## Проверка плана [дата]

### Файлы
- План: <путь>
- Спецификация: <путь>

### Требования без покрытия: N
- [CRITICAL] Требование §X.Y «<текст>» — нет шага в плане

### Шаги без требования: N
- [WARNING] Шаг #N «<название>» — не связан ни с одним требованием спецификации

### Нарушения зависимостей: N
- [CRITICAL] Шаг #N использует результат шага #M, который идёт позже

### Шаги без верифицируемого результата: N
- [WARNING] Шаг #N «<название>» — нет измеримого критерия готовности

### Структурные ошибки: N
- [WARNING] Шаг #N — TODO/TBD без значения / дублирует шаг #M

### Итог: OK / требует доработки
```
