Перепроверь результаты доработки. Выполни ревью, устрани ошибки.

Поддерживаемые аргументы:
- Путь к файлу/директории — ограничить scope
- `--no-fix` — только отчёт, без правок
- `--strict` — строгие пороги: функции >30 строк, вложенность >3
- `--skip-tests` — пропустить запуск тестов

## Алгоритм

1. **Определи scope**
   - Если передан путь в `$ARGUMENTS` — работай только с ним
   - Иначе: `git diff HEAD` (включает staged + unstaged)
   - Если diff пустой — сообщи: «Нет изменений для проверки. Укажи файл или сделай `git add`.»

2. **Ревью изменённых файлов** — проверяй только то, что входит в scope:
   - Ошибки логики и синтаксис
   - Нарушения архитектуры проекта
   - Безопасность: hardcoded secrets, injection, небезопасные chmod
   - Качество: функции >50 строк, вложенность >4 (если `--strict`: >30 строк, >3), дублирование
   - Обработка ошибок

3. **Устрани найденное** — исправь напрямую в коде (если не передан `--no-fix`)
   - Исправляй только то, что нашёл — не рефакторь surrounding code
   - Если правка рискованная (меняет API/интерфейс) — вынеси в `[WARNING]`, не трогай

4. **Проверь результат**
   - Bash-скрипты: `bash -n <file>`
   - Python: `python3 -m py_compile <file>`
   - Если есть тесты и не передан `--skip-tests` — запусти релевантные

## Правила

**Запрещено:**
- Выдумывать проблемы без конкретного файла и строки
- Исправлять код вне scope
- Трогать `Edit.old_string` при редактировании (ломает поиск)
- Повторно находить проблему, которую только что исправил в этой сессии

**Severity:**
- `[CRITICAL]` — логическая ошибка, уязвимость, сломанный синтаксис
- `[WARNING]` — качество, риски, требует решения автора
- `[INFO]` — стиль, минорные улучшения (не исправляй без явного запроса)

## Формат вывода

```
## Ревью [дата]

### Scope
- git diff: N файлов / указан путь: <path>

### Исправлено: X
- [CRITICAL] file.py:42 — описание → что сделано

### Требует решения: Y
- [WARNING] file.sh:65 — описание (почему не исправлено автоматически)

### Чисто: Z файлов
```
