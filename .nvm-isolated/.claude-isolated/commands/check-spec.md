Проверь внимательно спецификацию на соответствие поставленным задачам. Проверь на наличие ошибок.

Поддерживаемые аргументы:
- Путь к файлу спецификации — если не передан, файл определяется автоматически по алгоритму ниже
- Задачи берутся из контекста разговора (запрос пользователя, тема сессии)

## Алгоритм

1. **Определи scope**
   - Если имя/тема задачи известна из контекста разговора — ищи файл по имени в `docs/superpowers/specs/`
   - Если передан путь в `$ARGUMENTS` — работай с указанным файлом
   - Иначе: ищи последний изменённый файл в `docs/superpowers/specs/`
   - Если не найден — сообщи: «Не найдена спецификация. Укажи путь: `/check-spec path/to/spec.md`.»

2. **Прочитай и разбери спецификацию**
   - Выдели все требования (функциональные и нефункциональные)
   - Выдели ограничения и допущения
   - Выдели критерии приёмки / DoD

3. **Проверь полноту и корректность**
   - Покрыты ли все поставленные задачи хотя бы одним требованием?
   - Есть ли требования без связи с задачами (лишние / устаревшие)?
   - Есть ли противоречия между требованиями?
   - Есть ли неоднозначные формулировки («быстро», «удобно», «при необходимости» без критериев)?
   - Есть ли требования без критерия проверки (нет DoD)?

4. **Проверь структурные ошибки**
   - Нумерация, ссылки на несуществующие разделы
   - Потерянные плейсхолдеры (TODO, TBD, ???)
   - Несогласованные термины (одно понятие — два разных названия)

5. **Составь отчёт** (см. формат ниже)
   - `[CRITICAL]` — требование отсутствует, противоречие, задача без покрытия
   - `[WARNING]` — неоднозначность, нет критерия проверки, лишнее требование
   - `[INFO]` — стиль, минорные улучшения

## Правила

**Запрещено:**
- Придумывать задачи, которых не было в исходном описании
- Редактировать спецификацию без явного запроса
- Писать «вероятно подразумевается» без конкретной ссылки на текст

## Формат вывода

```
## Проверка спецификации [дата]

### Файл
- <путь к spec-файлу>

### Задачи без покрытия: N
- [CRITICAL] Задача «<название>» — нет ни одного требования

### Требования без задачи: N
- [WARNING] Требование §X.Y «<текст>» — не связано ни с одной задачей

### Противоречия: N
- [CRITICAL] §X.Y vs §A.B — описание конфликта

### Неоднозначности: N
- [WARNING] §X.Y — «<фраза>» без критерия измерения

### Структурные ошибки: N
- [WARNING] §X.Y — TODO/TBD без значения / битая ссылка

### Чисто: OK / требует доработки
```
