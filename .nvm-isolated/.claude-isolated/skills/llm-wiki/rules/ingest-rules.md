# Правила операции ingest

## Source Type Resolution

Перед чтением файла-источника определить reader:

```
1. ext = lowercase расширение файла (например: ".py", ".md")
2. Найти ext в domain-map.source_types
3. Если найдено:
   a. reader = source_types[ext].reader
   b. Загрузить @rules:readers/{reader}.md
   c. Применять extract-правила данного reader'а на шаге 3 (извлечение сущностей)
4. Если не найдено:
   a. Предупредить: "Тип файла {ext} не в source_types. Обработать как plain text?"
   b. AskUserQuestion: продолжить как plain text | пропустить файл
   c. Если plain text: искать только явные именованные понятия (существительные,
      аббревиатуры ≥ 3 упоминаний)
```

---

## Основные принципы

### Неизменность источников
Исходные файлы **никогда не модифицируются**. Только чтение через Read tool.

### Компаундируемость
При обновлении существующей страницы — добавлять новую информацию, не удалять старую.
Старые факты остаются. Новые приписываются источнику с датой.

### Синтез, не копирование
Контент wiki-страницы — переработанная информация из источника. Дословное копирование запрещено.
Исключение: SQL-запросы и технические конфигурации могут цитироваться в code-блоках.

## Алгоритм ingest (пошагово)

### Шаг 1: Загрузка контекста
```
1. Читать {wiki_dir}/domain-map.json → домены, entity_types, cross_domain_rules
2. Читать {wiki_dir}/schema.md → конвенции
3. Читать {wiki_dir}/index.md → список существующих страниц вики
```

Переменные `wiki_dir` и `wiki_root` определяются в Phase 0 SKILL.md.

### Шаг 2: Определение домена
Сопоставить путь файла-источника с `source_paths` каждого домена в domain-map.
Если путь не совпадает ни с одним доменом:
→ Сообщить пользователю: "Файл не входит в известные домены. Добавить в domain-map?"
Если источник в `special_source_types.daily_notes.path_pattern` → определять домен по содержимому.

### Шаг 3: Чтение и извлечение сущностей

Для каждого `entity_type` домена:
1. Читать полный текст источника
2. Искать сущности по `extraction_cues` и синтаксическим паттернам загруженного
   reader'а (@rules:readers/{reader}.md из Source Type Resolution):
   - .md: narrative/frontmatter/headings/code_blocks
   - .py/.ts/.js: public_api/docstrings/types/imports
   - .sh: functions/flags/exports/comments
3. Для каждой найденной сущности определить:
   - Каноническое имя (например: "ClickHouse", не "кликхаус")
   - Тип (`entity_type`)
   - Количество упоминаний в файле
   - Ключевая информация о сущности (факты, характеристики, связи)

Проверить `cross_domain_rules`: если сущность из другого домена → использовать правило primary_domain.

### Шаг 4: Решение CREATE / UPDATE / SKIP

```
Для каждой найденной сущности:

IF страница НЕ существует в index.md/папке домена:
    IF количество_упоминаний >= min_mentions_for_page:
        → CREATE (wiki_status: "stub")
    ELSE:
        → SKIP, залогировать: "Недостаточно упоминаний: {entity}, count={N}, min={M}"

IF страница существует:
    Прочитать существующую страницу
    IF источник содержит информацию, которой ещё нет на странице:
        → UPDATE
    ELSE:
        → SKIP (источник уже учтён или информация дублируется)
```

### Шаг 5: Синтез контента

**Для CREATE:**
- Использовать шаблон `@template:wiki-page`
- Установить `wiki_status: "stub"`
- Добавить путь источника в `wiki_sources`
- Заполнить H1, определение, Основные характеристики
- Добавить WikiLinks на связанные сущности в `wiki_outgoing_links` frontmatter (только существующие страницы)
- НЕ создавать "мёртвые" WikiLinks
- Внешние URL (документация, тикеты) — в `wiki_external_links` frontmatter

**Для UPDATE:**
- Прочитать существующую страницу через Read tool
- Определить, в какой раздел добавить новую информацию
- Если раздела нет — создать новый H2
- Добавить путь источника в `wiki_sources` если ещё не там
- Обновить `wiki_updated` на текущую дату
- Добавить новые связанные страницы в `wiki_outgoing_links` (не удалять существующие)
- При наличии ≥ 3 источников и достаточном контенте — поднять `wiki_status`

**Правила повышения wiki_status:**
- `stub` → `developing`: источников ≥ 2, контент ≥ 10 предложений
- `developing` → `mature`: источников ≥ 4, все основные разделы заполнены

### Шаг 6: Разрешение противоречий

Если новая информация противоречит уже записанной на странице:
1. Не удалять старую информацию
2. Добавить оба варианта с явной атрибуцией:
   ```
   По [ссылка-источник1] (дата): [версия 1]
   По [ссылка-источник2] (дата): [версия 2]
   ```
3. Добавить пометку в lint-notes на странице (комментарий `<!-- ПРОТИВОРЕЧИЕ: ... -->`)

**Приоритет источников при конфликте:**
1. HLD-документы (`special_source_types.hld_documents`) — наивысший
2. Архитектурные заметки, Best Practices
3. Daily notes — наименьший

### Шаг 7: Обновление метафайлов

После обработки всех сущностей:
1. **`log.md`**: Добавить запись по шаблону `@template:log-entry` в конец файла (APPEND ONLY)
2. **`index.md`**: Добавить новые страницы в соответствующий раздел
3. **`schema.md`**: НЕ трогать

### Шаг 8: Отчёт пользователю

```
Операция: ingest
Источник: [путь к файлу]
Домен: [id домена]

Создано страниц: N
  + [путь/к/странице.md] (тип: {entity_type}, status: stub)

Обновлено страниц: M
  ~ [путь/к/странице.md] (добавлен раздел: {название})

Пропущено: K
  - {entity_name}: {причина}

Следующий шаг: /llm-wiki lint {домен}
```

## Особые случаи

### Daily notes
Файлы из `!Daily/` могут содержать сущности любых доменов. Алгоритм:
1. Прочитать файл
2. Для каждого домена из domain-map проверить extraction_cues
3. Сгруппировать найденные сущности по доменам
4. Обработать каждую группу по стандартному алгоритму

### Неподдерживаемые типы файлов

**Excalidraw:**
Файлы `.excalidraw.md` содержат JSON-данные диаграммы, не читаемый текст.
→ SKIP с сообщением: "Excalidraw файлы не поддерживаются в ingest"

**Бинарные и compilation output:**
Файлы `.pyc`, `.whl`, `.so`, `.exe`, `dist/`, `build/`, `node_modules/`, `__pycache__/`
→ SKIP с сообщением: "Бинарный или compilation-output файл: {путь}"

**Неизвестное расширение:**
Расширение не найдено в domain-map.source_types.
→ AskUserQuestion: продолжить как plain text | пропустить файл

### Файлы без frontmatter
Обрабатываются штатно. Отсутствие frontmatter у источника не является ошибкой.

### Большие файлы (>500 строк)
Читать файл полностью. Если Claude не помещает в контекст — обработать по частям,
сохраняя промежуточные результаты через `log.md`.
