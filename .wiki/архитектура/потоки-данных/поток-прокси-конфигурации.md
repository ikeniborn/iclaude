# Поток настройки прокси

Последовательность операций при конфигурации HTTP/HTTPS-прокси в iclaude: от ввода URL до запуска Claude Code с активным прокси.

## Основные характеристики

**ID потока:** `proxy-configuration-flow`

**Шаги:**

| Шаг | Компонент | Действие |
|-----|-----------|---------|
| 1 | `cli-main` | Получение proxy URL от пользователя |
| 2 | `validate-proxy-url` | Валидация формата URL и протокола |
| 3 | `resolve-domain` | Резолюция домена в IP (только для HTTP) |
| 4 | `parse-proxy-url` | Извлечение credentials и хоста |
| 5 | `credential-storage` | Сохранение в `.claude_proxy_credentials` (chmod 600) |
| 6 | `configure-proxy` | Установка `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` |
| 7 | `test-proxy` | Тест HTTP (`http://www.google.com`) и HTTPS (`https://www.anthropic.com`) |
| 8 | `cli-main` | Запуск Claude Code с активным прокси |

**Разветвление по протоколу:**
- HTTPS → прямо к `parse_proxy_url` (домен сохраняется как есть)
- HTTP → `resolve_domain_to_ip` (fallback-цепочка: getent → host → dig → nslookup), затем `parse_proxy_url`
