# Защита данных доступа

Механизмы защиты данных доступа (прокси, OAuth-токены, API-ключи) в iclaude.

## Основные характеристики

**Хранилища и меры защиты:**

| Файл | Содержимое | Защита |
|------|-----------|--------|
| `.claude_proxy_credentials` | URL прокси, user/password | chmod 600, в `.gitignore` |
| `.credentials.json` | OAuth access/refresh token, `expiresAt` | chmod 600 (через `credential-storage`) |
| `.claude_config` | API-ключи (DEEPSEEK_API_KEY и аналоги) | chmod 600, никогда не коммитится |

**Правила:**
- Данные доступа никогда не попадают в git (`.gitignore`)
- Пароль прокси скрыт по умолчанию; для отображения требуется `--show-password`
- Компонент `credential-storage` (строки 1587–1745) централизует все операции чтения/записи

## Уязвимость undici (proxy MITM)

Библиотека `undici` (используется Claude Code) **не верифицирует** сертификаты целевого сервера при проксировании HTTPS ([HackerOne #1583680](https://hackerone.com/reports/1583680)).

**Меры:**
- Использовать только доверенные прокси
- Предпочитать `--proxy-ca` вместо `--proxy-insecure`
