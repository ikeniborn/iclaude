# Поток настройки прокси

Последовательность операций при конфигурации HTTP/HTTPS прокси в iclaude — от ввода URL до запуска Claude Code.

## Основные характеристики

**Диаграмма:** `docs/architecture/diagrams/data-flow-proxy-configuration.md`

### Этапы (13 шагов)

1. Пользователь предоставляет proxy URL
2. Валидация формата URL (`validate_proxy_url`)
3. Определение протокола (HTTP vs HTTPS)
4. **HTTP**: резолвинг домена в IP (цепочка: `getent` → `host` → `dig` → `nslookup`)
5. Парсинг URL: credentials, хост, порт
6. Сохранение credentials в `.claude_proxy_credentials` (chmod 600)
7. Загрузка credentials
8. Конфигурация окружения
9. Установка переменных окружения
10. Тестирование соединения (`test_proxy`)
11. HTTP-запрос: `http://www.google.com`
12. HTTPS-запрос: `https://www.anthropic.com`
13. Запуск Claude Code CLI с прокси

### Ветвление по протоколу

| Протокол | Обработка домена | Рекомендация |
|----------|-----------------|-------------|
| **HTTPS** | Домен сохраняется как есть; TLS SNI и Host header корректны | Рекомендуется |
| **HTTP** | Домен конвертируется в IP; может нарушить аутентификацию | Только если HTTPS недоступен |

### Переменные окружения после настройки

```bash
HTTPS_PROXY="https://[CREDENTIALS]@proxy:port"
HTTP_PROXY="https://[CREDENTIALS]@proxy:port"
NO_PROXY="localhost,127.0.0.1,github.com,..."
```
