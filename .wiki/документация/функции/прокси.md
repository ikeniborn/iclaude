# Прокси (HTTP/HTTPS)

Управление HTTP/HTTPS прокси-сервером для перенаправления трафика Claude Code через корпоративный или локальный прокси. Прокси настраивается при запуске iclaude и передаётся в Claude Code через переменные окружения.

## Основные характеристики

### Поддерживаемые протоколы

| Протокол | Статус | Рекомендация |
|----------|--------|--------------|
| HTTPS | Полная поддержка | Рекомендуется |
| HTTP | Полная поддержка | Только для localhost |
| SOCKS5 | Не поддерживается | Вызывает краш приложения |

SOCKS5 не работает из-за ограничений библиотеки undici. Обходной путь — использовать Privoxy как переходник HTTP→SOCKS5.

### Формат URL

```
http://[CREDENTIALS]@host:port
https://[CREDENTIALS]@host:port
```

Специальные символы в пароле нужно URL-кодировать: `@` → `%40`, `:` → `%3A`.

### Настройка сертификатов

Для HTTPS прокси с самоподписанным сертификатом:

```bash
# Безопасный способ (рекомендуется)
./iclaude.sh --proxy https://proxy:8118 --proxy-ca ./proxy-cert.pem

# Небезопасный способ (не рекомендуется)
./iclaude.sh --proxy https://proxy:8118 --proxy-insecure
```

Экспорт сертификата:
```bash
openssl s_client -showcerts -connect proxy:8118 < /dev/null 2>/dev/null | \
  openssl x509 -outform PEM > proxy-cert.pem
```

## Критическая уязвимость undici

Библиотека undici **не проверяет сертификаты** целевых HTTPS серверов при работе через прокси ([HackerOne #1583680](https://hackerone.com/reports/1583680)). Прокси-сервер может видеть и модифицировать все запросы к Anthropic API, включая API-ключи, код проекта и персональные данные. Следует использовать только доверенные прокси-серверы.

## Применение в контексте iclaude

Прокси сохраняется в `.claude_config` (chmod 600, не в git) и загружается при каждом запуске. При запуске с `--pii-proxy` трафик проходит через цепочку: Claude Code → PII proxy → корпоративный прокси → Anthropic API.

Совместимость с другими режимами: прокси работает одновременно с `--router`, `--pii-proxy`, `--sandbox-microvm`.
