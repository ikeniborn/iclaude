# Модульная структура iclaude (lib/)

iclaude v4.0 реализован как модульный bash-скрипт. Модули загружаются из `lib/` в строгом порядке фаз. Главный скрипт: `iclaude.sh`.

## Основные характеристики

### Модули (17 модулей в lib/)

| Модуль | Путь | Назначение |
|--------|------|-----------|
| `core` | `lib/core/init.sh` | `init_environment()` — глобальные переменные и экспорты |
| `command` | `lib/command/usage.sh` | `show_usage()` — справка по командам |
| `proxy` | `lib/proxy/` | Настройка и тестирование прокси |
| `nvm` | `lib/nvm/detect.sh`, `setup.sh` | Определение пути к claude binary |
| `oauth` | `lib/oauth/token.sh` | Управление OAuth токенами |
| `router` | `lib/router/` | Claude Code Router интеграция |
| `lsp` | `lib/lsp/` | LSP-серверы (TypeScript + Python) |
| `config` | `lib/config/` | Чтение `.claude_config` |
| `lockfile` | `lib/lockfile/` | Управление версиями (lockfile) |
| `update` | `lib/update/` | Обновление Claude Code |
| `launcher` | `lib/launcher/launch.sh` | `launch_claude()` — финальный запуск Claude Code |
| `statusline` | `lib/statusline/` | Установка статуслайна |
| `chrome` | `lib/chrome/` | Chrome integration (отключена по умолчанию) |
| `ohmyposh` | `lib/ohmyposh/` | Oh My Posh темы |
| `pii-proxy` | `lib/pii-proxy/` | PII-прокси сервер и установка |
| `sandbox` | `lib/sandbox/microvm.sh`, `install.sh` | Firecracker microVM |
| `graphify` | `lib/graphify/` | Graphify knowledge graph |

### Порядок загрузки (фазы)

```
Phase 0  → lib/core/init.sh          (init_environment)
Phase 2–8.1 → feature modules        (proxy, nvm, oauth, router, ...)
Phase 14 → command dispatch          (case statement по флагам)
```

### Определение пути к claude binary (nvm/detect.sh)

Порядок поиска `get_nvm_claude_path()`:

1. `$npm_prefix/bin/claude` (symlink)
2. `bin/claude.exe` (native binary, v2.1.114+, ~237MB, не в git)
3. `cli.js` через `node` (legacy pre-v2.1.114)

### Ключевые экспорты (init.sh + nvm/setup.sh)

| Переменная | Значение |
|------------|---------|
| `ISOLATED_NVM_DIR` | `.nvm-isolated/` |
| `CLAUDE_CONFIG_DIR` | `.nvm-isolated/.claude-isolated/` |
| `NPM_CONFIG_PREFIX` | `$ISOLATED_NVM_DIR/npm-global` |

`CLAUDE_CONFIG_DIR` экспортируется до запуска Claude — используется хуками и настройками.

### launch.sh — финальный запуск

`launch_claude()` в `lib/launcher/launch.sh` выполняет итоговый `exec claude [args]` с настроенными переменными окружения. При `--pii-proxy` запускает фоновый Python-сервер. При `--router` запускает `exec ccr code`.

## Изоляция конфигурации

`CLAUDE_CONFIG_DIR` всегда указывает на `.nvm-isolated/.claude-isolated/` — Claude Code хранит свои настройки, хуки, сессии и историю в этой изолированной директории, не в `~/.claude/`.

Bubblewrap (bwrap) удалён в марте 2026: создавал 0-байтные заглушки в `.claude/` других проектов.
