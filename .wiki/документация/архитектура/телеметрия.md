# Телеметрия и мониторинг

Исследование источников данных о сессиях Claude Code и вариантов построения стека мониторинга (Prometheus + Grafana). Дата: 2026-04-14.

## Основные характеристики

### Доступные источники данных

| Источник | Метрики | Доступность |
|----------|---------|-------------|
| `stats-cache.json` | messages, sessions, tools, токены, cache hit/miss | Всегда |
| `sessions/*.json` | session_id, startedAt, cwd | Всегда |
| `history.jsonl` | user messages, commands | Всегда |
| PII proxy `/api/metrics` | masked_items_total, uptime | Только `--pii-proxy` |
| `telemetry/*.json` | tool usage, agent_type, cachingEnabled | Всегда |

### Реальные метрики кэша (апрель 2026)

| Модель | Cache hit rate |
|--------|:-------------:|
| claude-sonnet-4-5 | ~94% |
| claude-opus-4-5 | ~91% |
| claude-sonnet-4-6 | ~91% |
| claude-haiku-4-5 | ~84% |

### Недоступно без инструментации

- Cache hit rate по дням (`dailyModelTokens` не включает cache-разбивку)
- Длительность API-запросов
- Tool calls по типам (Read/Edit/Bash) — только общий count
- Стоимость по дням (`costUSD: 0` во всех записях)

## Варианты архитектуры мониторинга

**Вариант 1 (минималистичный):** Stop hook → `session-summary.py` → `metrics/*.prom` → Prometheus → Grafana. Сложность: ~2-3 часа.

**Вариант 2 (оптимальный):** Расширить `lib/pii-proxy/server.py` — парсить `response.usage` и экспортировать в Prometheus format через `/metrics`. Добавляет per-request cache breakdown и latency.

**Вариант 3 (полный стек):** OpenTelemetry + Pushgateway + PostToolUse spans. Docker Compose с Prometheus + Grafana + otel-collector. Сложность: 2-3 дня.

## Расположение файлов

- `stats-cache.json`: `.nvm-isolated/.claude-isolated/stats-cache.json`
- `sessions/`: `.nvm-isolated/.claude-isolated/sessions/`
- `history.jsonl`: `.nvm-isolated/.claude-isolated/history.jsonl`
- Telemetry: `.nvm-isolated/.claude-isolated/telemetry/1p_failed_events.*.json`
