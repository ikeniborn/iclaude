# Типичные сценарии использования

Пошаговые инструкции для наиболее частых задач с iclaude.

## Основные характеристики

### Сценарий 1: Deploy на новый сервер (без системного npm)

```bash
# 1. Клонировать репозиторий (включает .nvm-isolated/)
git clone https://github.com/ikeniborn/claude.git && cd claude

# 2. Починить симлинки после git clone
./iclaude.sh --repair-isolated

# 3. Создать глобальный симлинк (требует sudo)
sudo ./iclaude.sh --create-symlink

# 4. Использовать глобально из любой директории
iclaude
```

Экономия: не требует `apt install npm` (~200MB+). Готово за 3 команды.

### Сценарий 2: Обновление изолированного Claude Code

```bash
./iclaude.sh --check-isolated   # проверить текущую версию
./iclaude.sh --isolated-update  # обновить (без sudo!)
./iclaude.sh --check-isolated   # проверить новую версию
```

### Сценарий 3: Временное переключение на системную установку

Если есть и изолированная, и системная установка:

```bash
./iclaude.sh --system   # принудительно использовать системную
./iclaude.sh            # вернуться к изолированной (по умолчанию)
```

### Сценарий 4: Работа через корпоративный прокси

```bash
# Настроить прокси с CA-сертификатом
./iclaude.sh --proxy https://[CREDENTIALS]@proxy.company.com:8118 \
             --proxy-ca ./proxy-cert.pem

# Или сохранить в .claude_config и запускать без флагов
echo 'PROXY_URL=https://[CREDENTIALS]@proxy.company.com:8118' >> .claude_config
echo 'PROXY_CA=./proxy-cert.pem' >> .claude_config
./iclaude.sh
```

### Сценарий 5: Запуск с максимальной защитой

```bash
# microVM + PII Proxy
./iclaude.sh --sandbox-microvm --pii-proxy
```

### Сценарий 6: Экономия на токенах через Router

```bash
# DeepSeek для рутинных задач, Claude для сложных
./iclaude.sh --router
```
