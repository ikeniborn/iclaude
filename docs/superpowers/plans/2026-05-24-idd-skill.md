# Intent-Driven Design (IDD)

IDD captures *why* before *how*. Run before `/brainstorm` to anchor the spec to real objectives — preventing specs that are precisely wrong (right HOW, wrong WHAT/WHY).

## When to use

Before `/brainstorm` on non-trivial features: new modules, API changes, architectural decisions.

**Skip when:** hotfix, typo, formatting change, or the feature's intent is already documented.

## Process

Ask five questions one-by-one. Wait for answer before asking the next.

1. **Objective** — What are we building and why does it matter?
2. **Desired outcomes** — What observable states prove success (from the user's perspective)?
3. **Health metrics** — What must not degrade? Name the metric that won't be sacrificed for the primary goal (Goodhart's Law protection).
4. **Constraints** — Architectural or technical constraints?
5. **Stop rules + autonomy** — When should I halt and escalate? What decisions can I make autonomously vs. require your confirmation?

After all five answers:

1. Write `docs/superpowers/intents/YYYY-MM-DD-<topic>-intent.md` using the template below.
2. Run:
   ```bash
   git add docs/superpowers/intents/
   git commit -m "docs(idd): add intent doc for <topic>"
   ```
3. Say: "Intent doc ready. Run /brainstorm next."

## Intent doc template

```markdown
# Intent: <topic>

**Date:** YYYY-MM-DD
**Status:** draft

## Objective
[Answer to Q1]

## Desired Outcomes
- [observable state 1]
- [observable state 2]

## Health Metrics
- [metric that must not degrade]

## Constraints
- [architectural or technical constraint]

## Autonomy Level
[Decisions Claude makes without asking]

## Stop Rules
[Conditions that require escalating to user]
```

## Common mistakes

- **Skipping questions:** Ask all five. Missing stop rules creates runaway implementations.
- **Vague outcomes:** "better UX" fails. "user completes checkout in < 3 clicks" passes.
- **Solutions in outcomes:** Outcomes describe *states*, not *implementations*.
- **Forgetting to commit:** The doc must be committed before brainstorming starts — brainstorming Step 1 scans project files and picks it up automatically.
```
