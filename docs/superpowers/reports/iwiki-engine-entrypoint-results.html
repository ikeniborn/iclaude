Резюме спецификации

Stable iwiki engine entrypoint: canonical IWIKI_ENGINE_DIR · статус: approved (design)
Файл: docs/superpowers/specs/2026-06-30-iwiki-engine-entrypoint-design.md

Проблема. Движок iwiki — это Python-модуль, запускаемый через uv run --project <engine-dir> python3 -m iwiki_engine, а не бинарь на PATH. Модель пробует command -v iwiki_engine, не находит, ошибочно «диагностирует» отсутствие в PATH и уходит в раскопки исходников. Рецепт запуска и цепочка резолвинга зарыты в шаге 4 каждого SKILL.md, вводная проза намекает на бинарь, единой канонической точки входа нет.

Требования по секциям

СекцияТребование
A Лаунчер экспортирует канонический IWIKI_ENGINE_DIR. Резолвер iwiki_export_engine_dir() в lib/iwiki/detect.sh экспортирует переменную в первый существующий путь с pyproject.toml. Порядок: (1) ${SCRIPT_DIR}/plugin/iwiki/engine (in-repo, всегда свежий, переиспользует _iwiki_engine_dir); (2) иначе новейший ${CLAUDE_CONFIG_DIR}/plugins/cache/*/iwiki/*/engine (sort -V | tail -1). Вызывается внутри source_iclaude_config в lib/config/env-map.sh — отдельным вызовом после apply_iclaude_env_map, не через ${!ICLAUDE_@} sweep.
B Единый канонический блок «Engine invocation» в начале всех 4 SKILL.md (iwiki-init, iwiki-ingest, iwiki-query, iwiki-lint): явно — движок это Python-модуль, не PATH-бинарь (никогда не запускать command -v iwiki_engine / iwiki_engine --help); одна каноническая команда с IWIKI_ENGINE_DIR первым, цепочкой-фолбэком и fail-loud выходом; исправить вводную прозу (убрать ${CLAUDE_PLUGIN_ROOT}/engine); заменить дублирующую цепочку в шаге 4 ссылкой на верхний блок.
C Усиление установки в lib/iwiki/install.sh install_iwiki() после uv sync — две раздельные проверки. (1) Engine-health smoke: python3 -m iwiki_engine status читает только индекс (без config / сети), чистая JSON-строка доказывает, что venv синкнут и модуль импортируется; status / lint / validate не зовут Config.load() и не могут HALT: на отсутствующих параметрах — поэтому health и проверка параметров намеренно разделены. (2) Parameter check: отдельный probe загрузчика конфига — python3 -c "from iwiki_engine.config import Config; Config.load()", который кидает ConfigError (exit 2) при отсутствии IWIKI_LLM_BASE_URL или IWIKI_LLM_KEY; при провале — пер-переменные предупреждения: required ICLAUDE_IWIKI_LLM_BASE_URL, ICLAUDE_IWIKI_LLM_KEY; optional (defaulted) ICLAUDE_IWIKI_EMBED_MODEL. (3) Вызвать резолвер из (A) и напечатать итоговый IWIKI_ENGINE_DIR. Всё non-fatal, но видимо.
D Verification / tests: shell-тест резолвера (in-repo dir в этом репо; новейший cached при скрытом in-repo); skill smoke (из scratch-каталога без plugin/iwiki/engine блок резолвится через cache glob, ... status работает); install smoke (status печатает JSON независимо, без config; при unset IWIKI_LLM_BASE_URL / IWIKI_LLM_KEY probe Config.load() выходит non-zero и срабатывают пер-переменные предупреждения); regression-grep, что command -v iwiki_engine / iwiki_engine --help нигде не инструктируются.
E Docs (iwiki keep-current): обновить docs/wiki/iwiki.md (движок — модуль, не PATH-бинарь; IWIKI_ENGINE_DIR — канонический entrypoint, экспортируется на launch; порядок резолвинга in-repo → newest cached); затем iwiki:iwiki-ingest на изменённый источник и /iwiki-lint.

iwiki Engine Entrypoint — план реализации
Файл: docs/superpowers/plans/2026-06-30-iwiki-engine-entrypoint.md
