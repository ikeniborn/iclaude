# verify.md — расширение диалога после перепроверки

**Дата:** 2026-04-29  
**Scope:** `.nvm-isolated/.claude-isolated/commands/verify.md`

## Проблема

Текущий алгоритм линеен: найти → исправить → проверить. После этого команда завершается, а `[WARNING]`-пункты («требуют решения автора») остаются без взаимодействия. Пользователь должен повторно вызывать `/verify` и вручную указывать, что исправлять.

## Решение: Вариант A — «Линейный диалог»

### Изменения в алгоритме

Текущие шаги 1–4 остаются без изменений. Добавляется **шаг 5**.

**Шаг 5 — Диалог по WARNING:**

```
Для каждого WARNING из раздела «Требует решения»:
  - Пропустить, если помечен [DECLINED] в текущей сессии
  - Спросить: «WARNING #N: <описание>. Исправить? (y/n)»
  - y → исправить → GOTO шаг 1 (полный перезапуск с тем же scope и флагами)
  - n → пометить [DECLINED], перейти к следующему WARNING

После обхода всех WARNING → вывести финальный отчёт
```

**Правила перезапуска:**
- Возврат к шагу 1 с тем же `$ARGUMENTS` и флагами (`--strict`, `--skip-tests` и др.)
- `[DECLINED]`-пункты не поднимаются повторно в текущей сессии
- Новые WARNING, появившиеся после правки, проходят через диалог в следующем витке

### Изменения в формате вывода

Добавляется раздел `### Отклонено: Z`:

```
## Ревью [дата]

### Scope
- git diff: N файлов / указан путь: <path>

### Исправлено: X
- [CRITICAL] file.py:42 — описание → что сделано

### Требует решения: Y
- [WARNING] file.sh:65 — описание (почему не исправлено автоматически)

### Отклонено: Z
- [DECLINED] file.sh:65 — описание (отказ пользователя в этой сессии)

### Чисто: N файлов
```

При каждом перезапуске цикла `[DECLINED]`-пункты не попадают обратно в «Требует решения».

## Что не изменяется

- Шаги 1–4 (scope, ревью, исправление, проверка синтаксиса/тестов)
- Поддерживаемые аргументы (`--no-fix`, `--strict`, `--skip-tests`, путь)
- Severity-система (`[CRITICAL]`, `[WARNING]`, `[INFO]`)
- Запрет трогать код вне scope

## Отклонённые варианты

**Вариант B (пакетный выбор):** пользователь выбирает номера WARNING списком. Сложнее формализовать в `.md`, один перезапуск в конце снижает надёжность.

**Вариант C (AUTO/CONFIRM):** делит WARNING на автоматические и требующие подтверждения. Нужна логика классификации — избыточно для текущей задачи.
