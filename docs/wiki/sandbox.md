# microVM Sandbox (Firecracker)

Runs Claude Code inside a Firecracker microVM for kernel-level process isolation. The VM boots from a pre-built Ubuntu 22.04 rootfs, mounts the isolated NVM environment and the project workspace via virtio-blk block devices, and exposes SSH over a TAP network interface. Claude Code is launched in the guest over SSH, with workspace files synced between host and guest. See [[architecture#Overview]] for the broader iclaude module structure.

## Guest Topology

```
Host                        Guest (172.16.0.2)
────────────────────        ────────────────────────────────
firecracker (KVM)      →    PID 1: iclaude-guest-init
tap-iclaude-1               sshd (pubkey only, iclaude user)
172.16.0.1 (host)           /dev/vda → rootfs (ext4, rw, session copy)
                            /dev/vdb → nvm.img (ext4, ro) → /mnt/nvm
                            /dev/vdc → workspace.img (ext4, rw) → /workspace
```

All guest processes run as the non-root `iclaude` user (uid 1000). Root SSH login is disabled. KVM provides hardware virtualization via `/dev/kvm`; the guest kernel is a Firecracker-compatible vmlinux. Firecracker version is `v1.11.0`; guest kernel is Linux `6.1.102`; rootfs base is `ubuntu-22.04-v1.10`.

## Detection

`lib/sandbox/detect.sh` provides three detection functions:

- `detect_linux_distro()` — reads `/etc/os-release`, normalizes ALT Linux IDs (`alt`, `altlinux`, `altserver`, `altworkstation` → `altlinux`), returns `distro:version`.
- `check_distro_microvm_support()` — gates on Ubuntu ≥ 22.04, Debian ≥ 10, ALT Linux ≥ 10; allows unknown/other distros without blocking.
- `detect_kvm_support()` — verifies Linux, rejects WSL1, checks `/dev/kvm` exists and is readable.
- `detect_microvm_binary()` — checks for the `firecracker` binary at `$MICRO_VM_BIN_PATH` (default `$ISOLATED_CONFIG_DIR/bin/firecracker`).

## Guest Init

`lib/sandbox/guest-init.sh` is the guest PID 1 process, injected into `rootfs.ext4` by `_inject_rootfs_guest_init()` at install time. On boot it:

1. Mounts kernel filesystems (`proc`, `sysfs`, `devtmpfs`, `devpts`, `tmpfs` for `/dev/shm`, `/run`, `/tmp`).
2. Brings up the loopback interface.
3. Writes `/etc/resolv.conf` with `8.8.8.8` and `1.1.1.1` (Firecracker's kernel `ip=` cmdline sets routing but does not configure DNS).
4. Mounts `/dev/vdb` read-only at `/mnt/nvm` (NVM image containing `.nvm-isolated`).
5. Mounts `/dev/vdc` read-write at `/workspace` (project directory, populated by host via SSH rsync or tar-over-SSH).
6. Creates the `iclaude` user (uid 1000, shadow password `*` so SSH pubkey auth is allowed without a locked account).
7. Sources `/workspace/.iclaude-guest-env.sh` (written by host before VM start) to import environment variables.
8. Starts `sshd` with `UsePAM no`, `PermitRootLogin no`, `AllowUsers iclaude`, `PubkeyAuthentication yes`, `PasswordAuthentication no`.
9. Enters a zombie-reaping `while true; wait; sleep 60` loop. A `SIGTERM`/`INT` handler (`_graceful_shutdown`) syncs filesystems, remounts rootfs read-only (clears the ext4 dirty flag), and exits PID 1, causing a kernel panic that terminates the Firecracker process.

## Installation

`install_microvm()` in `lib/sandbox/install.sh` downloads three components from their canonical URLs (configured in `lib/sandbox/versions.json`) and performs rootfs setup. All binaries are stored in `$ISOLATED_CONFIG_DIR/bin/` which is covered by `.gitignore`.

**Downloaded components:**

| Component | Version | Approx. size |
|---|---|---|
| `firecracker` binary | v1.11.0 | ~10 MB |
| `vmlinux` kernel | 6.1.102 | ~40 MB |
| `rootfs.ext4` | ubuntu-22.04-v1.10 | ~300 MB download / 2048 MB after resize |

Downloads use `_curl_download()` with proxy support (`PROXY_URL`, `PROXY_CA`, `PROXY_INSECURE`). On TLS exit code 35 (old OpenSSL cannot verify cert chain), the function retries with `--insecure --proxy-insecure` and warns the user.

SHA-256 hashes are stored in `versions.json`. If no hash is present in the file and `MICRO_VM_*_SHA256` env vars are not set, the function computes the hash after download and saves it (Trust-On-First-Use / TOFU). Sidecar `.version` files track the installed version of each component; an already-current component is skipped without re-downloading.

`_resize_rootfs()` uses `truncate` + `e2fsck` + `resize2fs` to grow `rootfs.ext4` to `MICRO_VM_ROOTFS_SIZE_MB` (default 2048 MB); the base Ubuntu image occupies ~265 MB.

**TAP networking** is set up by `_setup_microvm_network_or_instruct()`. It creates a `tap-iclaude-1` interface with host IP `172.16.0.1/24` (or derived from `MICRO_VM_NET_SUBNET`), enables IP forwarding, and adds iptables MASQUERADE NAT rules. Requires `sudo`; if unavailable, manual commands are printed instead.

**SSH key pair** (`ed25519`, no passphrase) is generated by `_generate_microvm_ssh_key()` and stored at `$ISOLATED_CONFIG_DIR/ssh/microvm`. The public key is baked into `rootfs.ext4`'s `/home/iclaude/.ssh/authorized_keys` via `debugfs`.

**Rootfs state machine** tracks applied upgrades in `rootfs.state`. Current states: `v3` (jq + DNS) → `v4` (CA bundle) → `v5` (/tmp tmpfs fix) → `v6` (resize) → `v7` (rsync for delta sync). `--install-microvm` applies missing upgrades without re-downloading the rootfs image.

**rsync bundle** (`_inject_rootfs_rsync_bundle()`). The guest rsync cannot be a bare copy of the host binary: host (e.g. Ubuntu 24.04 / glibc 2.39) and guest (Ubuntu 22.04 / glibc 2.35) differ, so the host rsync needs `GLIBC_2.38/2.39` symbols and `libpopt.so.0` the guest lacks — it fails with `error while loading shared libraries` (exit 127). Instead a *self-contained bundle* is injected into `/opt/iclaude-rsync/`: the host rsync (`rsync.bin`), its full `ldd` lib closure, AND the host dynamic loader; `/usr/bin/rsync` becomes a wrapper that runs `rsync.bin` via the bundled loader (`--library-path`), isolated from guest libc. This is glibc-version independent and verified to run in an Ubuntu 22.04 / glibc 2.35 guest. The injection is idempotent (a `<rootfs>.rsync-bundle` marker holds the host rsync's sha256) and applied to existing `v7` rootfs images on `--install-microvm` without a state bump. If rsync is missing on the host or the bundle cannot be built, the launcher falls back to tar-over-SSH — see [[launcher#microVM Workspace Sync]].

**Install command:**
```bash
./iclaude.sh --install-microvm
```

Requires `jq`, `curl`/`wget`, and `sudo` (for TAP setup and `debugfs` rootfs injection). Will not run while Firecracker is active (aborts with an error listing the PIDs).

## Runtime (microvm.sh)

`lib/sandbox/microvm.sh` manages the VM lifecycle: slot allocation, Firecracker JSON API boot configuration, workspace sync, Claude Code invocation over SSH, and clean shutdown.

Multiple concurrent sessions are supported via a slot model. Each slot is assigned a unique IP pair and TAP interface:
- Slot N → host IP `base+2N+1`, guest IP `base+2N+2`, TAP `tap-iclaude-{N+1}`
- Example with default subnet `172.16.0.0/26`: slot 0 → host `172.16.0.1`, guest `172.16.0.2`, `tap-iclaude-1`

Flags that are not meaningful inside the guest (`--chrome`, `--ide`) are stripped before launching Claude Code via SSH.

## Guest Environment & Authentication

`configure_guest_environment()` writes `/workspace/.iclaude-guest-env.sh` (chmod 600, sourced then deleted at launch) carrying the guest's `ANTHROPIC_BASE_URL`, proxy/`NO_PROXY`, model, router, and `CLAUDE_CONFIG_DIR=/workspace/.claude-guest` settings.

Authentication is forwarded explicitly: if the host has `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_AUTH_TOKEN`, or `ANTHROPIC_API_KEY` set (the host typically authenticates via `CLAUDE_CODE_OAUTH_TOKEN` from `.claude_config`, exported by [[config#Environment Variable Export]]), each is escaped via `_sh_escape_val()` and exported into the env file. Without this the guest has no credential — there is no `.credentials.json` file to copy for env-token hosts — and Claude Code reports `Not logged in · Run /login`. The credential-copy step only handles file-based OAuth (`.credentials.json` → `.claude-guest`), so env-token forwarding is the path that makes the guest logged in. See [[launcher#microVM Workspace Sync]] for how `.claude_config` itself is kept out of the synced workspace.

## Status

`check_microvm_status()` in `lib/sandbox/status.sh` reports:

- KVM availability
- Firecracker binary path and version
- vmlinux path and size
- rootfs.ext4 path, size, and state version (v3–v7; warns on upgrade needed)
- rootfs size vs. `MICRO_VM_ROOTFS_SIZE_MB` (warns on ENOSPC risk if below 80% threshold)
- nvm.img presence
- TAP interface (`tap-iclaude-1`) IP configuration
- Current configuration variables
- RAM warning if `MICRO_VM_MEM_MB` < 2048 (Claude Code RSS ~600 MB)
- Snapshot directory and count

**Status command:**
```bash
./iclaude.sh --check-microvm
```

## Configuration Variables

| Variable | Default | Purpose |
|---|---|---|
| `MICRO_VM_ENABLED` | `false` | Enable microVM on launch |
| `MICRO_VM_VCPU` | `2` | vCPU count for the guest |
| `MICRO_VM_MEM_MB` | `2048` | Guest RAM in MB (minimum 2048 recommended) |
| `MICRO_VM_NET_ENABLED` | `true` | Enable TAP networking |
| `MICRO_VM_NET_SUBNET` | `172.16.0.0/26` | Subnet for slot IP allocation |
| `MICRO_VM_NET_TAP_IFACE` | `tap-iclaude` | TAP interface name prefix |
| `MICRO_VM_ROOTFS_SIZE_MB` | `2048` | Target rootfs size after resize |
| `MICRO_VM_SNAPSHOT_ENABLED` | `false` | Enable Firecracker snapshots |
| `MICRO_VM_MOUNT_WORKSPACE` | `true` | Mount project dir as /workspace |
| `MICRO_VM_LOG_LEVEL` | `warn` | Firecracker VMM log level |
| `MICRO_VM_INSECURE_DOWNLOAD` | `false` | Skip TLS verification on downloads |
| `MICRO_VM_BIN_PATH` | `$ISOLATED_CONFIG_DIR/bin/firecracker` | Firecracker binary path |
| `MICRO_VM_KERNEL_PATH` | `$ISOLATED_CONFIG_DIR/bin/vmlinux` | Kernel image path |
| `MICRO_VM_ROOTFS_PATH` | `$ISOLATED_CONFIG_DIR/bin/rootfs.ext4` | Rootfs image path |
| `MICRO_VM_NVM_IMG` | `$ISOLATED_CONFIG_DIR/bin/nvm.img` | NVM block image path |
| `MICRO_VM_FC_SHA256` | — | Override SHA-256 for firecracker binary |
| `MICRO_VM_KERNEL_SHA256` | — | Override SHA-256 for vmlinux |
| `MICRO_VM_ROOTFS_SHA256` | — | Override SHA-256 for rootfs |
